# 跨机构调研方法与覆盖范围

这次把“量化岗位”按一笔投资决策的生命周期定义。从想法、数据、定价、组合、下单、撮合、清算、风险、运营、产品与合规，一直到平台和硬件。HR、销售、通用财务等职能在同一公司确实存在，只有职责与量化产品或交易运营直接相关时才单独进入技术课程。

## 行业范围

| 机构层 | 业务目标 | 容易误读为同岗的差异 |
|---|---|---|
| 中国量化私募 | 策略净效用、容量、稳定投产 | 同名 Quant Developer 可能负责因子测试、研究基础设施、订单或行情；以职责对象为准 |
| 公募与系统资管 | 基准约束、投资目标、资金流、产品跟踪与规模 | ETF 指数研究与增强研究关注指数方法、申赎和主动风险，长短仓对冲的约束不同 |
| 对冲基金与系统团队 | 策略边际贡献、组合实施与风险预算 | Researcher、PM、Data Strategies 的责任分别偏研究证据、资本与风险、数据特征 |
| 交易商、做市和自营 | 可执行价格、库存、数据速度、交易一致性 | Trader、Algo Developer、Pricing Developer、Core Engineer 的分工随公司而变 |
| 券商、期货与衍生品 | 执行服务、结构定价、专门品种研究、交割与保证金 | 同叫量化研究，卖方模型和对客风险通常有额外需求 |
| 交易所和清算 | 交易规则、市场公平和违约/流动性管理 | 清算风险、交易监控和买方策略风控的对象、授权、时点不同 |
| 指数和数据供应商 | 可靠计算、变更管理、数据产品与终端交付 | 指数方法论、参考数据版本和历史重算往往比研究收益重要 |

## 证据规则

1. 先从机构招聘官网及高校就业系统发布的招聘原稿查找，优先细粒度职位，搜索摘要可证明的范围限于显示内容。
2. 将真实名称登记为具名岗位。公司公开团队只够登记方向。网页跳转、动态载入、403/502 和历史公告状态直接记在对应入口。未公开内部 JD、失效职位和登录后信息不能靠推测补齐。
3. 同一职位多城市和级别归并，不按招聘人数计数。机构算各个用人主体，Citadel 与 Citadel Securities 各有公开招聘。按主要产出标主要岗位族，跨岗的能力从相邻实验读取。
4. 关键词是公开证据。后续的选型、替代方案、系统架构和教程均是基于职责推导，不用于推断机构内部系统或当前是否仍在招聘。
5. 本版的新增线索继续留档，便于找到公开材料后增补。天演资本、黑翼资产、赫富投资的本轮可读资料未形成稳定、可独立核对的逐条登记。幻方正式网站可见科研介绍，当前未找到足以登记的招聘职责。

## 技术如何跨公司比较

- **先对齐时间尺度。** 日频回测主要消耗历史数据读取、横截面计算和候选迭代。行情与执行热路径主要消耗解析、排队、内存访问与网络。在线尾延迟与离线吞吐的测量口径不同。
- **再对齐状态所有权。** 配置、审批和订单有明确的权威状态。研究、监控和 TCA 可以有多个模型或派生版本。数据层如何选 MySQL、Kafka、ClickHouse、Redis，取决于事务、回放、查询和延迟目标的分工。
- **最后找可验证产出。** 研究员提交反证和时间外结果；交易员提交成交和执行差额；后交易提交可追溯的资金仓位；风控提交限额、压力和差异解释；SRE 提交数据缺失恢复和 SLO；产品提交指数方法与持有人可读解释。
