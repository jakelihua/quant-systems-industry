# 十周训练与学习记录

课程按每周 8–12 小时设计，能写 Python 和基础 SQL 后即可进入。项目已经运行的结果在本仓库证据目录，个人掌握程度以自己提交的复现和解释为准。

| 周次 | 深入主题 | 需要亲手交出的东西 | 验收 |
|---|---|---|---|
| 1 | 市场结构、日历、PIT、公司行动 | 数据字典和 PIT 反例的 SQL，标记 source/exchange/receive/available 时间 | 给定修订后能重算当时可知值，并说明空值如何影响回测 |
| 2 | Alpha 假设、标签、横截面、市场状态 | 因子设计备忘录与手工验算。用一份点时资产池划分训练和验证 | 能识别重叠标签和复权/退市问题。列出至少两个反证 |
| 3 | 时间外验证、多重尝试、成本容量 | 复跑前推，保存每年训练截止点和候选评分，固定参数做未用段验证 | 修改未来收益不改变此前选择。以 20/60/120 窗口和不同成本归纳模型风险 |
| 4 | 组合优化、风险暴露与归因 | 约束权重生成器，加行业/风格/换手约束与失败降级说明 | 比对 TE、尾部 ES、冲击、敞口和风险贡献是否自洽 |
| 5 | L1/L2、深度、集合竞价、数据恢复 | 缺序号回放、盘口快照恢复、生命周期测试。画 mid、spread 和 imbalance | 丢包、重复、冲突、乱序时有明确恢复路径 |
| 6 | OMS/EMS、仓位账本、TCA | 回放增量账本、重启故障和限额冲突，手算 IS | 现金和仓位对上，撤单中成交和重复回执不多记一次 |
| 7 | 期货、期权、ETF 产品细节 | 一张期货换月与保证金表，一张期权曲面与 Greeks 风险表，一张 ETF 申赎成本表 | 看盘能写出报价可执行性、基差口径、期权合约调整及冲击限制 |
| 8 | 低延迟、消息、SQL、可观测性 | 拿同一事件输入比较 in-memory、事务与批处理。给出 Go/Python 控制面或 C++ 热点实验 | 记录样本量、吞吐和尾延迟。处理故障时保持校验输出一致 |
| 9 | 机器学习与 AI 工作流 | 研究端比较朴素模型和候选 ML；运维端给出规则基线、只读诊断和评估夹具 | 训练与线上输入一致。评估真实证据引用、误报和工具拒绝。提交性能预算 |
| 10 | 结项、面试、公众号 | 提交可回放演示、复盘文章、系统设计单页和复现实验记录 | 5 分钟讲完问题、反证、工程证据与边界。另一人能按 README 跑通 |

## 面试自测与答案线索

- **为什么 Redis 不适合单独作为成交账本？** 先说真实成交属于权威事件，再谈缓存持久化、主从、TTL 和回放。给一个重发后按执行 ID 去重的证明。
- **Kafka 的 exactly-once 对券商订单有什么意义？** 平台流处理和外部副作用分开，说明为什么业务必须有幂等请求、状态查询和对账。
- **如何证明研究没偷看未来？** 画出事件、可知和执行时间，把未来价格或晚到修订替换后重跑断言。对前复权、成员快照和标签重叠单独说明。
- **为什么盘中看到价差却算不出套利？** 解释可执行的 bid/ask、IOPV 时延、篮子、交易成本、限额，以及只成一腿的风险。
- **为何尾部延迟更重要？** 同一负载下均值相同仍可能有完全不同的拥堵和丢包。给出行情年龄、序号和端到端分位数。
- **为何策略跑赢沪深 300 仍不够？** 检查同池等权、黄金暴露和成本后换手。将市场收益、资产配置和择时规则拆开讨论。
- **如何给智能运维 Agent 做评估？** 用含已知真因和证据 ID 的事故样本，和规则基线对照。用只读范围和拒绝测试验证权限。
- **有三个系统都显示仓位，听哪个？** 往回找交易回报账本与外部清算凭证，按最近确认全量和此后回报复算，保留在途状态及水位。

## 公众号选题与配图

1. **滚动前推比一次切分多验证了什么**。用逐年训练截止日和三个基准解释为什么七次选中同一窗口没有验证自适应的增益。
2. **一张订单撤了，为什么仓位还在增加**。画 ACK → 40 股 → 发撤单 → 又成 20 股 → 撤单确认 → 剩余 40 股撤掉，配执行差额账单。
3. **相同财报日期，怎么回测出两条净值**。用修订时间线和 SQL 对比当天可见值，说明未来数据怎样改写历史。
4. **八张量化盘，看的是八种不同问题**。用一个 ETF 折溢价、一条期货基差和一个期权组合讲盘口、研究、执行、风险的关系。
