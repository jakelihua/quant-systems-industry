## 技术为什么出现在量化 JD

| 技术 | 放在哪里与选择理由 | 主要失效场景和验收 |
|---|---|---|
| Python、NumPy、pandas | 特征分析、回测验证、自动化巡检；向量化和可读性便于迭代，热点交给底层数组内核或本地扩展 | 避免逐行 Python 对象循环，检查排序和对齐，按峰值内存、处理时间及财务结果一致性验收 |
| SQL、MySQL/InnoDB、Postgres | 订单、策略配置、限额、审批、清算状态的权威记录；用唯一约束、可控隔离和事务维持一致性 | 事务窗口过长、锁竞争、重试重入。用幂等键、现金守恒、锁等待和故障恢复验收。SQLite WAL 是本项目对照 |
| Go | 部署交付、行情归集、巡检、API 或运维控制面；goroutine、context 及 pprof 便于并发服务和排障 | 观察高峰下 GC、队列与网络排队，显式设超时、并发上限和背压；对 p99、重启恢复和数据完整性验收 |
| C/C++、Rust | 低延迟行情解析和执行热路径；控制内存布局与分配，Rust 类型与借用检查强化部分安全边界 | 小均值可能掩盖尾延迟。先 profile 队列、系统调用、cache miss、NUMA 和锁，再验证无数据丢失及相同输出 |
| Linux、TCP/IP、UDP、多播、Socket | 交易接入、队列、部署和排障；TCP 提供连接中有序字节流，行情多播常需应用层补包 | 测序号缺口、乱序、重复、时钟偏差与接收队列溢出。分别记录交易所、应用接收与决策时间 |
| CPU 亲和性、NUMA、无锁、RDMA、内核旁路、FPGA | 热路径延迟预算不足时才进入选型。分别处理线程迁移、跨节点访存、锁竞争、数据拷贝、内核开销或确定性硬件处理 | 验证负载和故障时的分位数、硬件依赖及回退路径。无锁仍可能在高竞争下重试。FPGA 是扩展研究方向 |
| Kafka | 分区内事件顺序、持久日志、多消费者回放。适合异步分发和保留事件历史 | 键选错会破坏需要的局部顺序。监控 lag，加业务事件幂等键。外部券商成交的副作用仍须独立去重和对账 |
| Redis | 热配额、参考数据缓存、带过期时间的状态读取；读延迟低 | TTL 与权威版本不同步、主从切换或持久化策略造成差异。限额到期或恢复时必须明确降级规则 |
| ClickHouse、kdb+/q、Parquet/Arrow | ClickHouse 列式扫描和聚合适合大批行情或 TCA；kdb+/q 面向时序探索；Parquet 适合离线列存文件 | 用真实谓词、列裁剪、压缩和回填测性能，记录 sort key 和 as-of 条件。OLAP 和缓存各有账本一致性边界 |
| Docker、Kubernetes、CI/CD | 镜像复现、研究 Worker、批处理和控制面的部署管理 | 区分 liveness、readiness、startup。网关状态未对账前保持不可接流量；新旧版本回放一致且有确定回退条件 |
| React / TypeScript | 看盘、审批、风控和数据质量界面；显式模型区分行情过期、部分成交、未知订单、已撤 | 明确显示时间戳和数据版本，避免自动重试造成重复操作、刷新丢状态。服务端仍执行限额和权限检查 |
| PyTorch/TensorFlow、GPU、DDP、AMP | 高吞吐训练及推理；DDP 同步梯度，AMP 权衡精度和吞吐；先验证时间外成本后价值，再扩规模 | 先做线性/树基线，分清数据加载与通信瓶颈。验证模型漂移、线上延迟、吞吐、复现和混合精度误差 |
| CPT、SFT、RLHF 与 Agent | CPT 继续预训练适配语料，SFT 学任务示范，RLHF 用人类偏好改进反馈目标。Agent 通过受控工具读取运行证据 | 先用检索和工具调用基线。权限、数据出口、可追溯事实和离线评估要独立设计。审批和交易风险规则由确定性服务执行 |
| R、Matlab、FRM/CFA/CPA | R/Matlab 常用于统计原型和复核，证书知识涉及风险、资产估值或会计口径 | 用可移植中间结果与 Python 独立交叉验证。单位、净价/全价、结算时间和费用双计最容易出错 |

## 架构设计题

组合风控系统的权威订单账本落 MySQL/Postgres，事件可靠分发采用 transactional outbox。Kafka 用 `account_id` 或 `order_id` 分区，取决于需要维持何种局部顺序。若账户风险需要跨多订单原子预占，按账户串行化或使用权威事务，再把派生行情与订单事件写 ClickHouse 分析。Redis 可以缓存只读风险快照，缓存携带版本与有效期。Go 适合实现运维服务和回放控制面。C++ 只在量化测量表明确有热路径瓶颈时进入。UI 显示账户与回放水位线。Agent 输出引用事件 ID 的诊断建议。

验收用例为进程在数据库提交后、Kafka 确认前崩溃。重试后消费者可能见到重复事件，`event_id` 唯一性保护账本。补发完成后用源端成交和资金证券余额作独立对账。
